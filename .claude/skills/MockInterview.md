# MockInterview.skill — 模拟面试 + 简历深挖

输入 JD 和简历，按岗位系统化出题、逐题追问、按能力维度产出差距报告。

---

## When to Use

- 用户提供 JD，想针对性准备面试
- 用户说："帮我模拟面试"、"面一下这个岗位"、"面 X 公司的 Y 岗"
- 用户想让 AI 盯着简历上的实习/项目经历往下深挖
- 用户想在真面试前做压力测试
- 用户想拿到一份差距报告，知道哪里弱、怎么补
- 用户上传了 JD 或简历文件，或只给了"公司名 + 岗位名"

---

## 核心规则（4 条，全程遵守）

1. **隐藏评分标准**：每题在出题阶段就写好三档标准（弱/合格/强）+ 强候选人参考答案，对用户隐藏，答完对照评分。没有标准，报告无法复现。

2. **锁定深挖**：每题锁定简历上一个具体动作，沿"工具 → 量级 → 你的判断 → 成果"逐层追问。一个动作挖完，再换下一个动作。挖完前不切换到别的经历、别的话题。

3. **双输入主线**：主线是 JD + 简历，追问锁定简历经历。仅 JD 是没有简历时的降级路径。

4. **按维度汇总**：每题挂 1–2 个能力维度，报告按维度收敛（如"技术纵深强、指标感弱"），不做逐题流水账。

---

## 四个角色

| 角色 | 中文 | 职责 |
|---|---|---|
| RECRUITER | 研究命题 | 研究公司/岗位，读取 JD 与简历，做简历×JD 交集分析，定义能力维度，生成锁定简历动作、带隐藏标准的题库 |
| INTERVIEWER | 考官 | 分轮出题，锁定简历动作深挖，凶狠程度可调 |
| ASSESSOR | 评估 | 拿隐藏标准给答案打档，记录自评信心与实际表现的落差 |
| REPORTER | 复盘 | 按维度出差距报告，给可背的强答案、反问清单、简历经历体检，驱动复训 |

---

## Phase 架构

```
PHASE 0 — 研究与命题（RECRUITER）
  Step 0.1 选择输入模式 + 接收输入（简历按格式调用官方读取 skill）
  Step 0.2 联网研究公司与岗位
  Step 0.3 简历 × JD 交集分析（仅 JD+简历模式）
  Step 0.4 定义能力维度框架
  Step 0.5 生成题库（锁定简历动作 + 隐藏标准）
  Step 0.6 读取读档
  Step 0.7 选择反馈模式与难度

PHASE 1 — 模拟面试（INTERVIEWER + ASSESSOR）
  分轮：行为面 / 简历深挖 / 案例设计 / 技术领域 / 反问环节
  每题：出题 → 自评信心 → 作答 → 锁定深挖 → 打档记录 → 反馈

PHASE 2 — 差距报告（REPORTER）
  维度雷达 / 逐题回顾 / 信心盲区 / 简历经历体检 / 弱项强答案 / 反问清单

PHASE 3 — 弱项复训（回到 PHASE 1）
  针对最弱 1–2 个维度换新题重测，形成测—补—再测
```

## PHASE 0 — RECRUITER：研究与命题

### Step 0.1 — 选择输入模式 + 接收输入

开场让用户二选一：

```
先选输入模式：

[JD + 简历]（主线，推荐）
  面试官视角：对着 JD，盯着你的简历经历追问。最接近真面试。

[仅 JD]（没简历或不方便传时）
  只按 JD 出通用题，问不到你的具体经历，深度打折。
```

**接收 JD**：粘贴文本 / 上传文件 / 只给"公司+岗位名"（后者进入 Step 0.2 联网还原岗位画像）。

**接收简历（按格式路由读取）**：

| 简历格式 | 读取方式 |
|---|---|
| .docx / .doc | 调用 docx skill 读取正文 |
| .pdf | 调用 pdf-reading skill 提取文本 |
| 图片（png/jpg/截图） | 视觉识别 / OCR 转文本 |
| .md / .txt / 直接粘贴 | 直接读取 |

判断规则参考 file-reading skill 的路由。读取完成后，先向用户简短汇报提取到的经历清单，确认无误再进入 Step 0.3。**本流程只处理提取后的文本，不自行解析二进制文件。**

### Step 0.2 — 联网研究

出题前先做研究，避免出通用题：

```
1. 公司：主营、近期动态、技术栈 / 产品线
2. 岗位：这个 title 在这家公司负责什么、汇报线、常见考察点
3. 公司自家相关产品：面 PM/技术岗常被问"你怎么看我们的 X 产品"，
   查清楚，让案例题落在真实产品上
4. 该岗位行业内的典型面试题型与评价标准
```

**来源标注**：研究结果标注来源。查不到的，说明"基于对该类岗位的通用理解"，不编造公司内部信息。

### Step 0.3 — 简历 × JD 交集分析（仅 JD+简历模式）

逐条扫描简历经历，与 JD 要考的能力做交集，分三类：

```markdown
## 简历 × JD 交集分析：{岗位}

| 经历 | 类别 | 判断依据 | 深挖方向 |
|---|---|---|---|
| {舆情分析实习} | ① 对口可深挖 | JD 要数据分析，这段对口 | 锁定"周报搜集"挖工具/量级/判断/成果 |
| {某项目一句话带过} | ② 太单薄需量化 | 只有结论，无过程和数字 | 逼出你负责哪块、产出多少 |
| {"主导了 XX 战略"} | ③ 可能被质疑 | 应届说"主导战略"易被压 | 压到细节，看是真做过还是润色 |
```

三类的命题意图：

- **① 对口可深挖**：命题主战场，锁定动作深挖
- **② 太单薄需量化**：出题逼出量级、成果、你个人负责的部分
- **③ 可能被质疑**：出题施压，看能否答实。目的是提前发现"会被问穿"的地方，不是把不实的说圆

交集分析结果对用户可见，由此生成的具体评分标准仍隐藏。

### Step 0.4 — 定义能力维度框架

为岗位定一套能力坐标（6–8 个维度），全程复用。维度从 JD 反推 + 岗位常识：

```markdown
## 能力维度框架：{岗位名}

| 维度 | 说明 | 权重 |
|---|---|---|
| D1 {维度名} | {这个岗位为什么考它} | 高/中/低 |
| D2 ... | ... | ... |
```

**参考（PM / Agent 类岗位，非固定）**：产品 sense、技术纵深、权衡取舍、指标与数据感、领域知识（Agent/LLM）、结构化表达、影响力/落地。其他岗位自行重定义（如后端岗有系统设计、工程质量、稳定性等）。

### Step 0.5 — 生成题库（锁定简历动作 + 隐藏标准）

按轮次生成题目。JD+简历模式下，每题锁定 Step 0.3 标出的某条简历经历的具体动作。评分标准与参考答案在出题阶段写好，全程隐藏，仅评分和复盘时内部使用。

```markdown
## 题库（内部，隐藏评分标准与参考答案）

### 轮次：{行为面 / 简历深挖 / 案例设计 / 技术领域 / 反问环节}

#### Q{n}. {题目}
- **锁定经历**：{简历里哪条经历的哪个动作}（仅 JD+简历模式）
- **交集类别**：① 对口可深挖 / ② 太单薄需量化 / ③ 可能被质疑
- **挂载维度**：D2 技术纵深、D4 指标感
- **真正考察**：{表面问 A，实则看是否具备 B 能力}
- **评分标准（隐藏）**：
  - 🔴 弱：{浅层/空泛回答的样子}
  - 🟡 合格：{及格线覆盖了什么}
  - 🟢 强：{优秀回答的要素——结构、数据、权衡、落地}
- **参考答案（隐藏）**：{2–4 句要点，评分时对照}
- **深挖链（预设，答得浅时用）**：{沿这个动作预写 2–4 层追问，逐层逼近工具→量级→判断→成果}
```

**简历深挖轮**是 JD+简历模式的核心轮：围绕 ① 类经历展开，每条经历一条深挖链。仅 JD 模式跳过此轮。

题量：每轮 3–6 题，总量 15–30 题，按岗位复杂度调整。

### Step 0.6 — 读取读档

```
检查 ./interview_saves/{岗位-slug}.md 是否存在
→ 存在：读取上次表现，展示
   "上次到第 X 轮，最弱维度是 Y，报告建议补 Z。
    这次针对弱项复训，还是完整重面一遍？"
→ 不存在：全新开始
```

### Step 0.7 — 选择反馈模式与难度

```
反馈模式：
  练习模式：每题答完立刻给参考答案和点评（学习用，早期推荐）
  考试模式：全程不反馈，最后统一出报告（模拟压力，临考前推荐）

考官凶狠度：
  温和 HR：追问克制
  深挖技术：顺技术细节往下钻
  Bar-raiser：高压追问，专找逻辑漏洞
```

用户说"随便/你定"时，默认练习模式 + 深挖技术，直接开始，不再追问。

## PHASE 1 — INTERVIEWER + ASSESSOR：模拟面试

### 每题循环

```
STEP 1 出题
  报出题目，说明第几轮第几题。一次一题，不剧透后面。

STEP 2 收集自评信心
  作答前请用户给自己打把握分（1–5 分），用于 PHASE 2 算信心落差。

STEP 3 用户作答

STEP 4 锁定深挖
  ASSESSOR 内部拿评分标准判断落档。
  答案含糊 / 空泛 / 只有结论 / 背模板：
    → INTERVIEWER 顺当前锁定动作往下问，逐层逼近：
        "具体什么场景？给个真实例子。"
        "用什么工具？一次/一周处理多少量？"
        "这些里你怎么筛的？标准谁定的？"
        "有没有你产出的东西被采纳/上报/上线的例子？"
    → 沿"工具 → 量级 → 判断 → 成果"逼近，直到答出硬信息，
      或用户明确答不上来（答不上来本身是一个信号，记录）。
  答案已具体、有结构、有数据/权衡：
    → 这个动作挖完，进入 STEP 5。

  硬规则：当前动作挖完前，不切换到别的经历、别的话题。
  凶狠度随 Step 0.7：温和 HR 挖 1–2 层，Bar-raiser 挖到底。

STEP 5 评分记录（ASSESSOR）
  拿隐藏标准打档（🔴/🟡/🟢），记录：
  - 落档 + 关键缺失
  - 自评信心 vs 实际落档（落差）
  - 挂载维度表现

STEP 6 反馈（分模式）
  练习模式：当场给落档、缺失、参考答案、一句改进建议
  考试模式：只记录，不反馈，进入下一题

STEP 7 换题 / 换轮
  一轮结束简短小结该轮印象，进入下一轮。
```

### 轮次

| 轮次 | 侧重 | 题型 |
|---|---|---|
| 行为面 | 经历、动机、协作 | STAR 类 |
| 简历深挖（主线核心） | 简历经历的真实性与纵深 | 锁定简历动作，沿工具/量级/判断/成果挖（仅 JD+简历模式） |
| 案例设计 | 产品/系统设计 | "设计一个 X"、"你怎么改进我们的 Y 产品" |
| 技术领域 | 领域纵深、硬知识 | 概念、方案权衡、领域前沿 |
| 反问环节 | 提问质量 | "你有什么想问我的？" |

### 用户控制

```
- "跳过这题" → 记为未作答，进入下一题
- "重答" → 覆盖上一次回答
- "换考试/练习模式" → 切换反馈模式
- "凶一点 / 温和一点" → 调凶狠度
- "直接出报告" → 中止面试，用已答题目进入 PHASE 2
```

## PHASE 2 — REPORTER：差距报告

触发：所有轮次结束，或用户说"出报告"。固定用此模板：

```markdown
# 差距报告：{公司} · {岗位}
日期：{日期} | 模式：{练习/考试} | 完成：{X}/{总题数} 题

## 一、总体印象
{3–4 句：整体表现、最突出的强项、最致命的弱项}

## 二、能力维度雷达
| 维度 | 表现 | 诊断 |
|---|---|---|
| D1 ... | 🟢 强 | {什么表现支撑这个判断} |
| D2 ... | 🟡 合格 | ... |
| D3 ... | 🔴 弱 | ... |

## 三、逐题回顾
| # | 题目 | 落档 | 真正考察 | 关键缺失 |
|---|---|---|---|---|
| Q1 | {简写} | 🟡 | {实则看什么能力} | {缺了什么} |

## 四、信心盲区
标出"自评高、实际弱"的题，真面试最易在此翻车：
| # | 自评信心 | 实际落档 | 落差 | 提醒 |
|---|---|---|---|---|
| Q5 | 5 分 | 🔴 弱 | ⬇️ 大 | {为什么高估了} |

## 五、简历经历体检（仅 JD+简历模式）
对被深挖过的每条经历给面试视角体检，只诊断不代写：
| 经历 | 撑不撑得起 JD | 缺的量化/证据 | 会被怎么问穿 | 补的方向 |
|---|---|---|---|---|
| {舆情实习} | 勉强 | 缺处理量级、被采纳案例 | 一追工具和量级就卡 | 把真实数字和 1 个案例补进简历 |
| {某项目} | 撑不起 | 只有结论无你的动作 | 问"你负责哪块"会卡 | 拆出你实际做的动作 |

保真边界：只指出哪条虚、往哪个方向补、会被怎么问穿；不替用户编经历，不把"打杂"改写成"主导战略"。虚的地方，方向是补出真实细节，不是包装。

## 六、弱项强答案
每个 🔴/🟡 维度：
### 弱项 1：{维度名}
- 暴露在：{哪些题}
- 可背的强答案：
  > {打磨好的强答案，用户改成自己的话即可背}
- 底层要补：{除了背答案还要练什么}

## 七、反问清单
针对这家公司和岗位，可反问的高质量问题：
1. {扎到岗位/公司真实痛点的问题}
2. ...

优先补的 1–2 个维度 + 复训方式（进入 PHASE 3）。
```

## PHASE 3 — 弱项复训

触发：报告出完后，用户选择复训。

```
1. 锁定报告中最弱的 1–2 个维度
2. RECRUITER 针对这些维度换一批新题（不重复，含新标准）
3. 回 PHASE 1 跑一轮小面试（只面弱项相关题）
4. REPORTER 出复训对比：这次 vs 上次，弱项是否改善
5. 循环至弱项转绿
```

## 各角色输出约定

| 角色 | 约定 |
|---|---|
| RECRUITER | 题库、标准、参考答案内部持有，只暴露题目。研究结果标注来源。 |
| INTERVIEWER | 一次一题。锁定一个动作深挖，挖完前不换题，不接受表面答案。用 `── 第X轮 ──` 标轮次。 |
| ASSESSOR | 静默工作，不打断节奏。打档依据标准，不依据印象。信心落差必录。 |
| REPORTER | 按模板输出。每个判断有据。强答案可直接背。 |

## Common Pitfalls

| # | 错误 | 正确 |
|---|---|---|
| 1 | 凭感觉打分 | 出题时写好三档标准，答完对照 |
| 2 | 追问挖两下就跳到别的经历 | 锁定一个动作挖到底再换题 |
